# Locator Add

You are tasked with auto-instrumenting React Native library components so that consumers get accessibility locators (testID, accessibilityLabel) for free via prop forwarding plus default derivation from semantic props (text, label, placeholder).

The tool ships in **library mode** only for v1: it modifies component definitions in libraries like `@practo/self-serve`. Consumer/app code is not touched. After the library is instrumented and republished, every consumer call site automatically gets a sensible testID without dev effort.

**Response format — always:**
- What was done (max 2-3 bullets)
- Exactly what the developer needs to do right now
- What happens next

Never narrate reasoning. Direct the next action.

> **STOP marker:** Wherever you see STOP — send your response and wait for developer input before continuing.

## Phase 1: Locate the library root and helper

The transform inserts an import for a `deriveTestId` helper. The helper lives at `<library-root>/src/utils/locator.ts` (a convention).

1. From the input path, walk upward until you find a `package.json`. That directory is the library root.
   - If multiple paths are passed, validate they all share the same library root. If not, abort: "Multiple library roots in input. Run the tool separately per library."
2. Check whether `<library-root>/src/utils/locator.ts` exists.
3. If it does **not** exist, create it with the contents below. This file is committed alongside the instrumentation — it's the runtime helper the inserted code calls.

```ts
// <library-root>/src/utils/locator.ts
// Generated by /devkit:locator-add. Used at runtime to derive testID strings
// from semantic props (text, label, placeholder). Consumer code can override
// any auto-derived testID by passing one explicitly.
export const deriveTestId = (
  text: string | undefined,
  suffix: string,
): string | undefined => {
  if (!text) return undefined;
  const slug = text
    .toLowerCase()
    .trim()
    .replace(/[^a-z0-9]+/g, '-')
    .replace(/^-+|-+$/g, '');
  return slug ? `${slug}-${suffix}` : undefined;
};
```

4. Note the helper's relative path from each target file's perspective — the transform computes this per-file.

## Phase 2: Run the jscodeshift transform

Resolve the absolute path to the transform: `<plugin-root>/scripts/locator-add.js`.

If devkit's `node_modules` doesn't exist (no `<plugin-root>/node_modules` directory), run:
```bash
cd <plugin-root> && npm install
```
Wait for completion. This is a one-time setup; subsequent runs reuse the install.

Then run the transform:

```bash
npx --prefix <plugin-root> jscodeshift \
  -t <plugin-root>/scripts/locator-add.js \
  --parser=tsx \
  --extensions=tsx,jsx,ts,js \
  [--dry] \
  --naming=<role|screen|full> \
  <input-path>
```

- Pass `--dry` only if `--dry-run` was specified.
- Pass `--naming=<value>` always (default `role`).
- Capture stdout and stderr. jscodeshift prints per-file status (`OK`, `skipped`, `error`) and a summary.

## What this command does NOT do

- Does not touch consumer / app code (only library files)
- Does not commit or push
- Does not detect cross-screen testID collisions (rare — handled by dev manually if it happens)
- Does not support iOS native, Android native, or React web (RN only for v1)
- Does not replace existing manual `testID={...}` attributes (idempotent skip)
- Does not auto-fix the runtime-UUID antipattern (`testID={\`x-${id}\`}`) — leaves alone, dev decides

## Failure modes

- **No package.json found** — input path isn't inside a recognized library. Abort with the error.
- **Helper file already exists with different content** — print the existing content and the proposed content; ask the dev to reconcile manually.
- **jscodeshift not installed and `npm install` fails** — print npm's error and ask the dev to install Node deps manually.
- **Transform errors on a file** — log per-file in the report, continue with the rest.
